# Tool bootstrap

> How to install and activate the project's core tools so the commands
> in [`AGENTS.md`](../AGENTS.md) actually work. This file is for
> **agents and new contributors** on a fresh machine. Keep it short
> and copy-pasteable.

## Required tools

- **uv** — project / build tool.
  Install instructions below.
- Language runtime for **python** — 3.12 or newer (`requires-python =
  ">=3.12"`); CI runs the gate on 3.12, 3.13 and 3.14. `uv` will fetch a
  matching interpreter itself, so no separate install is needed.
- **`jq`** — reads the Claude Code hook payloads in `.claude/settings.json`
  ([`hook-input.sh`](../.agents/hooks/hook-input.sh) falls back to `python3`
  when `jq` is missing; with neither on PATH, the hooks warn at session start
  and the destructive-command guard denies every Bash call until one is
  installed). Install: `apt-get install jq` / `brew install jq`.

## Install `uv`

[`uv`](https://docs.astral.sh/uv/) — fast Python package & project manager.

The canonical, automated bootstrap is
[`.agents/hooks/ensure-toolchain.sh`](../.agents/hooks/ensure-toolchain.sh): it
installs `uv` if it is missing, and is exactly what the Claude Code
`SessionStart` hook (and a Claude Code on the web setup script) run. From the
repo root:

```sh
sh .agents/hooks/ensure-toolchain.sh
```

What that does under the hood (and how to install by hand):

```sh
# Standalone installer (macOS / Linux):
curl -LsSf https://astral.sh/uv/install.sh | sh

# Or via pipx / brew / your OS package manager — see
# https://docs.astral.sh/uv/getting-started/installation/

uv --version   # verify
```

After install: `uv sync` materialises the project environment from
`pyproject.toml` and creates/updates `uv.lock` (or uses it when present).

## Activate the language toolchain

If this repo pins language versions, pick **one** pin file as the
source of truth — `.tool-versions` (read by both
[`asdf`](https://asdf-vm.com/guide/getting-started.html) and
[`mise`](https://mise.jdx.dev/getting-started.html)) or `mise.toml`
(`mise` only, richer config) — install either manager from its linked
docs, and run its `install` command inside the repo to materialise the
pinned versions. Neither pin file is generated by the template; add one
as part of project setup.

This repo pins no language version outside `pyproject.toml`, so neither
pin file is present: `uv sync` resolves and fetches the interpreter.

## Verify the bootstrap

Once the steps above are done, run the canonical verification gate:

```sh
make verify
```

If it succeeds on a fresh clone, the bootstrap worked.
